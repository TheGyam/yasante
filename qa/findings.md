# Findings

Confirmed issues, each with the run that showed it. Candidates still to be tested live in
the plans' audit notes.

| # | Found | Area | Finding | Evidence |
| :--- | :--- | :--- | :--- | :--- |
| F1 | 25-09-2026 | auth | **Sign-out never reaches the server.** `logout()` in `src/features/auth/store.ts` only clears tokens on the device; nothing in the app calls `POST /api/auth/logout/` or `/logout-all/`, though the backend has both. The refresh token (7 days) stays valid after signing out, so a copied token outlives the sign-out. | Run `SETUP-smoke-1011`, steps P6b–P6e: no logout line in `server.log`; `dbcheck` shows `revoked=0`. Code search: no caller. |
| F2 | 25-09-2026 | backend seed | **Every seeded account is unconfirmed.** `seed_db` predates email verification and leaves `email_verified=False`, so signing in as any seeded person goes to the code screen. Test data only, but it hides the normal signed-in path in local work. | Same run, P5b: `Check your email` after a correct sign-in; `dbcheck` before verifying shows `verified=False`. |
| F3 | 26-09-2026 | app (stylist sign-up) | **App crash after creating a stylist account (emulator; confirm on the phone).** Right after the sign-up request succeeded, React Native's renderer threw `IllegalStateException: addViewAt: cannot insert view [432] into parent [462]: View already has a parent` and the process died. It restarted cold, on `Check your email`. The sign-up switches mode to stylist while pushing the verify screen, which is the likely trigger. | Run `AUTH-01-20260926-0508`, capture `082-D2b` `app.log` (PID 16874), then `083-D2c` shows a new PID 22962 starting cold. |
| F4 *(candidate)* | 26-09-2026 | app (stylist request) | **The request screen mixes time zones.** `She asked for Tue 29 Sep, 10:00` is shown in London time, but the `Start at` picker under it shows the device's own time (**05:00** on an emulator not set to London). A stylist whose phone isn't on London time sees a different start time from the one the client picked, and any time she picks is read in her device's zone. | Dry run `SETUP-two-emus`, capture `016-stylist-sty-4`. To confirm in BOOK-01 A1 and on the phone. |
| F5 *(candidate)* | 26-09-2026 | app (forms) | **With the keyboard open, the first tap on a form button is lost.** It only closes the keyboard; the tap never submits (A4: 5 taps → 1 request; B5 needed four attempts). Users will tap `Sign in` twice. Likely `keyboardShouldPersistTaps` on the form ScrollView. | Run `AUTH-01-20260926-2221`, A4 (server log 02:28:28–45) and B5. To confirm on the phone. |
| F6 *(candidate)* | 26-09-2026 | app (email code) | **Reopening the app mid sign-up sends a new code by itself.** Each cold start on `Check your email` calls `POST /api/auth/email/start/`, so every launch sends an email and uses up the resend rate limit and cooldown. | Run `AUTH-01-20260926-2221`, B9 (mailbox email 2 at 02:50:59, no tap). |
| F7 *(candidate)* | 27-09-2026 | backend (bookings) | **A booking can be moved onto a day the stylist doesn't work.** `move` and `move/answer` both accept it; nothing checks working days (or clashes) on a move, although new requests only offer working-day slots. | Run `BOOK-01-20260926-2339`, M5: B2 moved to Mon 28 Sep 10:00 (server 11:36:47 `move` 200, 11:38:45 `move/answer` 200). |
| F8 | 27-09-2026 | app (stylist setup) | **The suggested page handle freezes at the first letter of the name.** `handle: draft.handle || toHandle(displayName)` sets the handle on the first keystroke (`q` for "QA Braids Kojo") and never updates it again, because it's no longer empty. One letter is below `HANDLE_MIN` (3), so `Continue` won't advance: a new stylist can't get past step 1 without noticing and rewriting the handle herself. Fix: track whether she has edited the handle, not whether it's empty. | Run `STYLIST-01-20260927-1851`, A2/A3 (`010-stylist-A3`); server `GET /api/stylists/by-handle/q/`. `app/stylist-setup.tsx` onChangeText. |
