## Other observations

1. **Deep Link `NOT_HANDLES` Routing Bug (F4, C5):** Both `search` and `saved` routes are missing from `NOT_HANDLES` in `src/shared/lib/links.ts`. Attempting to deep link `yasante:///search` or `yasante:///saved` erroneously treats these paths as stylist handles (`/stylist/search`, `/stylist/saved`), resulting in 404 Not Found.
2. **Look Lookup Identifier (L1):** Deep linking using fixture handle `look_seed_1` fails (404); the backend `/api/looks/<id>/` endpoint strictly requires a UUID.
3. **Look Composition Validation (P1):** In `app/looks/new.tsx`, posting a look requires selecting at least one style taxonomy tag (`disabled={!photoUri || !picked.length}`); otherwise the button is disabled with helper text "Tag the style so people can find it."
4. **Report Reason Conditional Input (R1b):** In `app/looks/options.tsx`, the freeform "What happened?" note input is only rendered when `reason === 'other'`. For preset reasons such as `reason-not-their-work`, no note input is shown and the report is sent directly.
5. **Stale Cache on Deleted Look Screen (R4):** In `app/looks/[id].tsx`, the screen renders `{look ? <LookThread ... /> : <EmptyState title="This look is gone" ... />}`. If the look was previously viewed in the same session, React Query retains stale data in cache when a background refetch returns 404, causing the client to render the deleted look (with a 404 error toast) rather than the "This look is gone" empty state.
