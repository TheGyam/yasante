## Other observations

1. **Critical Defect in Handle Suggestion (`app/stylist-setup.tsx:176`):**
   `handle: draft.handle || toHandle(displayName)`
   When the user begins typing a display name such as `QA Braids Kojo`, the very first character typed (`Q`) sets `draft.handle` to `"q"`. On subsequent characters, because `draft.handle` is now truthy (`"q"`), the auto-suggestion logic is bypassed and the handle never updates to reflect the rest of the name. Because `"q"` is only 1 character, it triggers `handleProblem: "At least 3 characters"`, permanently disabling the `setup-next` button unless manually edited. This defect prevented completing the setup wizard (steps A3 through A6b).
2. **Cascading Failures from Uncreated Stylist Profile:**
   Because Kojo could not finish the setup wizard, no stylist profile existed in the database, and Kojo's user account was never assigned the `stylist` role. Consequently:
   - Saving individual menu items (`POST /api/stylists/me/menu/`) returned HTTP 404: "No stylist profile yet".
   - Importing price lists (`POST /api/stylists/me/menu/import/`) returned HTTP 404: "No stylist profile yet".
   - Saving working hours (`PATCH /api/stylists/me/`) returned HTTP 404: "No stylist profile yet".
   - Saving payment methods (`PATCH /api/stylists/me/`) returned HTTP 404: "No stylist profile yet".
   - Importing portfolio photos (`POST /api/stylists/me/portfolio/`) returned HTTP 404: "No stylist profile yet".
   - Accessing the public stylist profile from the client (`GET /api/stylists/by-handle/q/`) returned HTTP 404: "No page here - This stylist doesn’t have a live page".
   - Booking requests (F1/F2) could not be initiated or evaluated across time zones.
3. **Skeleton Hang on Numbers Screen (`app/numbers.tsx:122`):**
   `useStylistNumbers()` specifies `enabled: !!user?.roles?.includes('stylist')`. When viewed by a user without the stylist role, the query is disabled and returns `undefined` without loading. The screen checks `{isLoading || !data ? <Skeleton height={320} /> : ...}`, causing the screen to remain permanently on the skeleton loader.
4. **UI Automator Idle State Timeouts:**
   React Native / Expo animations frequently prevented `uiautomator dump` from reaching an idle state (`ERROR: could not get idle state`). However, deep-linking, coordinate-based taps, and screenshot captures operated properly throughout the run.

## Audit (Claude, 27-09-2026)

page-name step suggests a handle with `handle: draft.handle || toHandle(displayName)`
(`app/stylist-setup.tsx`). On the first keystroke the handle is empty, so it becomes
`q`. From then on it isn't empty, so it never updates. Anyone typing their name letter
by letter, which is every keyboard, gets a one-letter handle, below `HANDLE_MIN = 3`, and
`Continue` won't advance. Setup never went live, Kojo never became a stylist, and every
later stylist call got `404` (`PATCH /api/stylists/me/` ×2, `POST …/menu/`,
