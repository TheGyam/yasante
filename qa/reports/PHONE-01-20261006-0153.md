## Other observations

1. **`qadb recover` on Android 16 (`SM-S918B`):** `qadb recover` (`adb shell am start -a android.intent.action.MAIN -c android.intent.category.LAUNCHER -p com.yasante.app`) fails on Android 16 with `Error: Activity not started, unable to resolve Intent`. Using `qadb link "yasante:///"` (`android.intent.action.VIEW`) reliably brings the backgrounded app to the foreground without restarting it.
2. **`qadb launch` when onboarding is already completed (`S1`, `S3`):** Because `qadb launch` starts the Expo development client via `yasante://expo-development-client?url=http%3A%2F%2Flocalhost%3A8082`, Expo Router treats `expo-development-client` as an unmatched deep link (`Unmatched Route / Go back`) when the welcome/onboarding screen is no longer intercepting initial navigation. Tapping `Go back` reveals the underlying Home or welcome screen.
3. **403 booking/request/check-in screens (`L2`, `L3`, `L4`):** While `L1` (`404` look) and `L5` (`404` invite) render explicit friendly not-found screens (`This look is gone`, `This invite doesn’t work`), `L2` (`booking-screen`), `L3` (`request-screen`), and `L4` (`check-in`) render an empty placeholder card with no user-facing "not yours / not found" message when the API returns `403` (`"That booking isn’t yours"`), and React Query continues retrying the `403` in the background.
